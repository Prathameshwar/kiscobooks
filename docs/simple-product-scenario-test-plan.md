# Simple product creation: 10-configuration test plan

Prepared: 2026-11-07. Status: local simulations and targeted native checks executed; see [results and limits](simple-product-scenario-results.md).
Scope: Simple product creation, configuration compatibility, validation, pricing, stock, UI and recovery. No VM update or deployment.

## Fixtures and configuration rules

Use 10 isolated configuration snapshots, with Simple mode selected in every successful baseline. Resolve company capabilities, effective Goods/Service configuration, default product-type revision, field metadata and actor permissions together; do not simulate compatibility by hiding controls alone. Record the effective settings and source revisions with each result.

Use a test company with a ready financial year, eligible group and base unit, permitted stock location, active reference masters, currency and published tax/pricing sources as applicable. IDs below are fixture references, not invented production IDs. Let D be a permitted opening date, M a manufacture date before D, and E an expiry date after D. Generate unique product names/codes per run; exercise automatic code generation separately.

Disabled counterparts use fresh isolated fixtures when capability flags are irreversible after use. Do not disable tracking or inventory in a company with posted stock just to run a negative case. Check that each requested configuration is publishable; report unsupported combinations separately from creation defects.

Opening unit cost is separate from purchase reference price. Compare exact decimal values and independently calculate opening valuation; do not change valuation rules to make old fixtures pass. Selling price may be zero where native policy permits it; provided purchase price, MRP and opening unit cost must be positive.

## Checks shared by the scenarios

- **Presentation:** friendly labels rather than keys such as `brand_id`; aligned fields, hints, errors and actions; readable required indicators; keyboard labels/focus; no clipped tables/buttons at desktop 1440, tablet 768 and mobile 390 pixels. Check all three supported themes on representative plain, batch and serialized forms.
- **Steps:** the current Simple UI introduces a separate Stock and prices step when batch or serial capture is available. Verify both that layout and the ordinary combined form. Continue/back preserves values and does not bypass final validation.
- **Dropdown behavior:** capture document navigation and network requests before/after kind, group, unit and dependent master changes. No full-page postback, flicker, unrelated value reset or duplicate submit. Allow necessary dependent-source refreshes; confirm bounded requests and clear loading states.
- **Create progress:** immediate styled feedback, locked submit while running, readable current stage and server-confirmed milestones for create/pricing/activation/tracking/opening as applicable. Skipped stages must not appear completed work; completion follows verified native status, not an elapsed timer. Focus success/errors and provide useful retry/wait messages.
- **Recovery:** double-click Create, delayed response, failed source lookup, transport timeout, reload during processing, retry and editable rejection. Reuse the same intent/idempotency key for uncertain results; completed stages are not repeated and stock is not posted twice. Editable validation failures let the user correct details.
- **Configuration drift:** publish a different effective snapshot while a draft is open. Recheck required/disabled/access changes, explicit clearing of retained values and source readiness before submit. Test the Advanced-mode-enabled guard separately: Simple creation must be unavailable rather than creating a mismatched product.
- **Native evidence:** compare submitted bodies, creation status, resulting product/unit/tax/pricing/tracking facts and opening quantity/value. Verify disabled data is omitted and invalid input causes no unintended effects. For live stock claims, inspect actual owner-service evidence and duplicate prevention.
- **Isolation:** a second company/actor cannot read, resume or submit another company's creation command or use its reference masters.

## Scope boundaries

Simple creation covers one product and its native default definition. Variant axes, multiple-SKU generation and advanced unit/tier/channel/currency/formula authoring are outside this form's test scope. Do not present omitted advanced controls as supported Simple inputs. Boundary limits are targeted validation checks here, not a performance/load certification.
